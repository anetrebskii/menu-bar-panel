# Menu Bar Panel

Нативное локальное приложение Swift/AppKit для Apple Silicon, macOS 14+. Собрано на macOS 26.5.2, Swift 6.3.2. Нет Electron, сети, аккаунтов и автозапуска.

**Статус: сборка готова; интеграционная приёмка заблокирована разрешениями macOS. Работа с настоящими чужими значками и восстановление их порядка на этом Mac ещё не проверены.**

## Запуск и необходимые разрешения

```sh
open 'dist/Menu Bar Panel.app'
```

При первом запуске кнопка встаёт крайней справа. Дальше macOS запоминает её место: если вы перенесли кнопку с Command-перетаскиванием, при следующих запусках она остаётся там. Через секунду после запуска и при смене экранов проверяется, что кнопка видна вне выреза. Только если она оказалась за вырезом, приложение пересоздаёт её крайней справа, чужие элементы не перетаскиваются. Позиция задаётся через используемый AppKit ключ `NSStatusItem Preferred Position`, который не является документированным API абсолютного размещения: гарантировать поведение всех будущих версий macOS нельзя.

Пока нет хотя бы одного разрешения, панель показывает список «Дайте доступ к строке меню» из двух пунктов: «Универсальный доступ» и «Запись экрана». У выключенного пункта кнопка «Открыть настройки» ведёт в нужный раздел Privacy & Security; добавьте там **Menu Bar Panel.app из dist** и включите. Состояние проверяется при каждом открытии панели. Если macOS предлагает перезапуск после записи экрана, перезапустите только Menu Bar Panel.

Разрешения выдаёт только пользователь. Приложение никогда не меняет TCC, SIP, чужие настройки и службы. Сборки подписаны Developer ID Application, Team MQKD7Z7V2L; релизы на GitHub нотаризованы. Последующие сборки с этой же identity сохраняют совместимое designated requirement.

**Если доступ уже включён для старой 0.1.0, но панель его не видит:** ошибка подтверждена в TCC log: старое разрешение привязано к прежнему ad-hoc cdhash, который менялся при пересборке. После перехода на стабильную подпись один раз замените старую запись Menu Bar Panel в Accessibility текущим `.app` из `dist` через `−` / `+` и включите её. Аналогично проверьте запись в Screen & System Audio Recording. Если macOS требует, перезапустите только это приложение. Нельзя перенести старое разрешение программно; агент переключатели не меняет. Это исправление причины повторной потери доступа, а не подтверждение, что новая сборка уже получила разрешения.

## Работа

Нажатие кнопки открывает ленту настоящих скрытых значков под кнопкой, в теме строки меню, чтобы снимки значков оставались видны. Правый клик по кнопке или «⋯» в конце ленты открывает «Обновить» (⌘R) и «Выйти из Menu Bar Panel» (⌘Q). Escape и клик снаружи закрывают ленту; ←/→ и Tab переходят между значками, Return и Space нажимают. Повторный запуск .app открывает панель уже работающего экземпляра. Лента шире 640 pt прокручивается.

При первом запуске приложение добавляет себя в объекты входа и дальше стартует вместе с Mac. Выключить можно в Настройки › Основные › Объекты входа; приложение не включит себя снова.

Выбор значка переносит его слева от нашей кнопки, и он остаётся там; самый левый видимый значок уходит за вырез и появится в панели. Нажатие на значок за вас не делается: он уже виден, нажмите его сами. На время переноса (около 0,1 с) курсор скрыт и возвращается на место. Обратно за вырез значок не возвращается: macOS принимает бросок только в видимую часть строки, и возврат требовал переставлять все соседние значки. Если перенос не удался, панель открывается снова с причиной. Индикатор микрофона macOS переставляет сама, он не учитывается.

## Релизы

Каждый пуш в `main` (кроме правок только в `.md` и `LICENSE`) запускает `.github/workflows/release.yml`: сборка на macOS, подпись Developer ID с hardened runtime, нотаризация, staple и релиз `v0.2.<номер запуска>` с `MenuBarPanel-<версия>-arm64.zip` и `SHA256SUMS`. Скачайте zip со страницы [Releases](../../releases), распакуйте и перенесите `Menu Bar Panel.app` в Applications.

Секреты репозитория задаёт `scripts/set-release-secrets.sh <key id> <issuer id> <AuthKey.p8>`: он выгружает из login keychain только Developer ID Application в .p12 со случайным паролем, добавляет ключ App Store Connect для notarytool и сохраняет всё через `gh secret set`. Локально `scripts/release.sh` делает то же самое через профиль notarytool `notary`.

## Сборка и проверки

Нужны Apple Command Line Tools с macOS SDK и Swift. Сборка без зависимостей и скачивания пакетов:

```sh
./scripts/build.sh
./scripts/package.sh
```

`build.sh` выбирает существующий Developer ID Application в keychain либо принимает `CODE_SIGN_IDENTITY` явно. Для сохранения разрешений используйте одну identity. Если её нет, скрипт останавливается. Для явно одноразовой сборки доступен `CODE_SIGN_IDENTITY=- ./scripts/build.sh`; её ad-hoc разрешения не сохраняются при изменениях. `BUILD_APP_PATH` позволяет собрать копию в другой каталог, не заменяя работающий экземпляр. Приватные ключи и сертификаты в ZIP не входят.

Продукт: `dist/Menu Bar Panel.app`. Архив: `dist/MenuBarPanel-0.1.1-arm64.zip` (приложение, полный исходный код, документы и доказательства). Сборка arm64; Intel не заявлен.

Для точной проверки TCC используйте LaunchServices, а не прямой запуск бинарника из доверенного терминала:

```sh
open -n -W --stdout "$PWD/evidence/diagnostics-launchservices.json" 'dist/Menu Bar Panel.app' --args --diagnose
```

`--diagnose` читает состояние без запроса разрешений и завершает только свой экземпляр. Включает реальные frame/onScreen собственной кнопки и проверку безопасной области выреза. `--show` открывает настоящую панель сразу после запуска для диагностики. `--appearance=light` / `--appearance=dark` меняют только тему панели для проверки; без них панель берёт тему строки меню. `--preview-setup` показывает экран разрешений при уже выданном доступе, только для проверки вида. `--diagnose` не переносит и не восстанавливает значки. `--trace-ui` пишет в stderr открытия/закрытия панели, коды клавиш и шаги переноса значков; обычный запуск этого не делает.

## Ограничения и доказательства

См. [evidence/verification.md](evidence/verification.md). Реальные меню, возврат порядка, Escape, Tab, внешние клики, две темы и позиционирование на обоих физических дисплеях пока не получили пользовательскую интеграционную проверку. Наличие устройства с вырезом и успешная компиляция сами по себе не закрывают эти проверки.

Public AppKit не позволяет встроить NSStatusItem другого процесса. Используются недокументированные WindowServer API и оконная snapshot-совместимость, исследованные в Ice; обновление macOS может нарушить их. Публичный ScreenCaptureKit не заменяет необходимый композитный захват offscreen menu windows в исследованной реализации. Не все системные/нестандартные status items допускают перенос. Приложение сообщает об отказе вместо подстановки вымышленных значков или меню.
